03 Execution order, run_daily.py:main()

  1. 1 fetch_market.py pulls today's OHLC + valuation for every TWSE-listed stock in two bulk calls, writes market_snapshot.json, appends one record per stock to history/{code}.json.
  2. 2 write_json.py joins the snapshot with history, runs indicators.py (SMA20/60, RSI14, MACD, MA cross) and labels.py (percentile valuation words) per stock, writes dashboard.json.
  3. 3 If Sheets secrets are set: write_sheet.py reads the watchlist tickers from 自選清單, overwrites 全市場 and 自選股詳情.
  4. 4 For each watchlist ticker, fetch_watchlist_news.py queries Google News RSS by company name.
  5. 5 write_sheet.write_watchlist_news() writes one row per news item to 自選股新聞. Only on the branch behind PR #5 — not on main yet.
  6. 6 If LINE secrets are set: alerts.py evaluates MA-cross / RSI-band triggers and new-announcement triggers, then send_line_push() posts one message per recipient.
⚠ Why the amber matters right now

main's daily.yml already has LINE_TEST_MODE=true, but main's alerts.py still always reads LINE_RECIPIENT_USER_IDS — the real list, dad included. PR #5 carries the fix onto main directly. Until it merges, any trigger firing on a scheduled run pushes to both real recipients regardless of test mode. Full writeup in status/decisions.md.
